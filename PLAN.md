# Plan: week by week

Status: Planned — implementation not started yet. Every box below is unchecked on purpose. Tick a box only when its done-criterion is true and linked.

Assumed pace: about 8–10 hours per week, 8 weeks. Free-GPU quota is the main schedule risk, so GPU-heavy work is front-loaded with buffer in weeks 7–8.

## Week 1 — Protocol and licence audit (M0)

- [ ] Re-read current free-tier limits for Kaggle and Colab; record them in `docs/compute.md`.
- [ ] Read the Qwen3-1.7B-Base licence file and model card; record the revision hash.
- [ ] Open each dataset card and upstream source (Aya Dataset, Aya Collection Telugu subsets, IndicAlign components, IndicXNLI, IndicSentiment, Belebele, FLORES-derived); write `DATA_LICENCES.md` (source, revision, licence, upstream notes, decision).
- [ ] Write `EVAL_PROTOCOL.md`: tasks, prompts, decoding, metrics, bootstrap settings, success criteria, the English-regression margin.
- [ ] Choose the tracker (W&B or MLflow) and record why.
- [ ] Freeze test sets: download, save with SHA-256 manifest, commit the manifest (not the data if the licence restricts redistribution).

Done when: protocol and licence files are committed and the test-set manifest exists.

## Week 2 — Eval harness and base baseline (M1)

- [ ] Repo skeleton: `src/`, `configs/`, `tests/`, `notebooks/`, pinned `requirements.txt`.
- [ ] Prompt templates for NLI, sentiment, Belebele MCQ, translation (both directions).
- [ ] Log-likelihood option scorer for classification/MCQ.
- [ ] Generation runner with fixed decoding and sacreBLEU chrF++ (store the signature).
- [ ] Bootstrap CI and paired bootstrap test utilities.
- [ ] Unit tests for each scorer using tiny hand-made fixtures.
- [ ] Run the base model (few-shot) and the official `Qwen3-1.7B` reference; log to the tracker.
- [ ] Measure tokens per word on a Telugu sample and Telugu-script output rate.

Done when: one command evaluates any model/adapter on all tasks, tests pass, and baseline numbers with CIs are logged. Write results into `results/baseline.md` from the logs, never from memory.

## Week 3 — Data pipeline and smoke run (M2, M3)

- [ ] Script to pull Telugu rows from Aya Dataset, selected Aya Collection subsets, selected IndicAlign components.
- [ ] Cleaning: Unicode normalisation (NFC), drop empty/too-short/too-long, script-ratio filter, exact and near-duplicate removal.
- [ ] Contamination filter against all test sets (exact + 8-gram); write the removal report.
- [ ] Split into train and validation with a fixed seed; write counts per source.
- [ ] Chat/instruction template applied consistently; check label masking (loss on responses only).
- [ ] Smoke run: ~100 steps QLoRA on a free GPU; log peak memory and tokens/sec; kill and resume from a checkpoint to prove resume works.
- [ ] Draft dataset card.

Done when: a deterministic build produces the splits, the contamination report is committed, and the smoke run resumes from a checkpoint.

## Week 4 — Main fine-tune, first pass (M4)

- [ ] Choose max sequence length and data mix from smoke-run throughput.
- [ ] Train configuration A (for example rank 16, alpha 32, attention + MLP targets, cosine schedule, fp16 compute, gradient checkpointing).
- [ ] Evaluate validation loss and a quick subset of benchmarks at checkpoints.
- [ ] Push adapter A to the Hub as private until the card is ready.

Done when: adapter A exists, the run is in the tracker with config and seed, and an evaluation on the full harness has run.

## Week 5 — Ablations and seeds

- [ ] Ablation: LoRA rank (for example 8 vs 16 vs 64) or data mix (human-written only vs human + translated), whichever the week-4 results justify; pick one axis.
- [ ] Extra seeds for the main configuration, as many as quota allows (target 3).
- [ ] Check the English regression subset for each trained model.
- [ ] Note any failed or discarded runs in `results/run-log.md` (including why).

Done when: the chosen ablation and at least one extra seed are finished, or the log states what quota prevented.

## Week 6 — Full evaluation and human study (M5)

- [ ] Write 50 fresh prompts (not from any training source); freeze them.
- [ ] Generate outputs from base+few-shot, fine-tuned, and the instruct reference; shuffle and anonymise.
- [ ] Rater 1 (author) and rater 2 (another Telugu speaker) score fluency, correctness, instruction following (1–5) and pairwise preference.
- [ ] Compute agreement (κ) and aggregate scores with bootstrap CIs.
- [ ] Final automatic benchmark tables for all systems.

Done when: all tables are generated by script from logged outputs, and rater sheets are archived (without personal data).

## Week 7 — Error analysis and write-up (M6)

- [ ] Read 30+ failures by hand; categorise (wrong script, repetition, hallucination, translationese, task confusion).
- [ ] Compare against pre-declared success criteria and state plainly whether they were met.
- [ ] Write the model card (outline in README) and finalise the dataset card.
- [ ] Add reproduction instructions and a one-command evaluation example.
- [ ] Publish adapter and model card on the Hugging Face Hub.

Done when: the model card is complete, limitations are written, and a fresh clone can re-run the evaluation.

## Week 8 — Buffer, polish, release

- [ ] Re-run anything that failed due to quota in earlier weeks.
- [ ] Update the README status line and site badge from "Planned" to what is true, with links to real runs.
- [ ] Short write-up (blog post or README section) of what worked, what did not, and what to try next.
- [ ] Add the project and its numbers to the resume and portfolio, linking logs rather than quoting from memory.

Done when: the status line, site and resume all match what the logs show.
