Telugu LoRA Eval

Fine-tune a small open-weight language model on Telugu instruction data with LoRA/QLoRA, then test whether it really beats the base model on held-out Telugu benchmarks and a small human-rated set. తెలుగు is the target language.

Status: Planned — implementation not started yet. Nothing here has been built, trained or measured, and no results are claimed.

View the plan repository on GitHub Week-by-week checklist

Why this project

Most AI projects call a hosted API. This one adapts a model, controls the data, and proves the change with an evaluation that is allowed to say “it did not help”.

The question: does parameter-efficient fine-tuning on open Telugu instruction data measurably improve a 1–3B model on held-out Telugu tasks, and what does it cost in English ability? A negative or mixed answer will be reported as such.

Approach

  1. Model: Qwen/Qwen3-1.7B-Base, Apache-2.0, Telugu listed among its supported languages (coverage quality to be measured, not assumed).
  2. Data: open Telugu instruction sets, filtered, with test-set overlap removed and the split frozen by hash.
  3. Training: QLoRA (4-bit base, LoRA adapters) with peft and transformers on a free T4 GPU.
  4. Evaluation: one harness, same prompts and decoding for base (few-shot), fine-tuned, and the official post-trained model as a reference.
  5. Report: confidence intervals, error analysis, model card, and a list of what did not work.

Evaluation design

Classification and QA

NLI, sentiment and reading comprehension scored by option log-likelihood. Accuracy and macro-F1 with 95% bootstrap intervals and a chance baseline.

Translation

English↔Telugu with chrF++ (sacreBLEU), signature recorded, paired bootstrap between systems.

Human-rated set

50 fresh prompts, blind and shuffled outputs, two Telugu-speaking raters, rubric for fluency, correctness and instruction following, agreement reported. Directional evidence only.

Safety checks

Contamination filter, English regression check, Telugu-script output rate, repetition rate.

Tech stack and compute

  • PyTorch, Hugging Face transformers, peft, datasets, bitsandbytes, trl
  • Weights & Biases or MLflow for tracking (chosen in week 1)
  • Free Kaggle and Colab GPUs; checkpoint and resume on every session; target cost ₹0 / $0, with any top-up capped and recorded first

Planned length: 8 weeks at roughly 8–10 hours a week.

Main risks

  • Free GPU quota and disconnects: short checkpointed runs.
  • Telugu tokenisation cost: measured first and reported.
  • Test contamination and licence chains: overlap filter and per-source audit.
  • Scores near chance for a 1.7B model: intervals and “no significant difference” stated when true.
  • Small, author-written human set: blind, two raters, called directional.
